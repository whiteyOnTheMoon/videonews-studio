# P2-01: Dormant independent host-approval persistence (migration 0022)

The existing worker source-export contract (#243) **requires a host permission distinct from an admin source's "approved" status**. Migration 0022 makes that permission a separate durable revisioned PostgreSQL object; it is not automatically derived from source records.

A separately authorized call to `vns.admin_change_source_host_approval` receives one action (`grant` or `revoke`), one hostname, a 20–300-character operator reason, expected host/source revisions, and a server-authenticated named administrator's UUID/auth version. PostgreSQL rechecks the active named admin under row lock and verifies the source snapshot revision. A grant is allowed **only** when a reviewed `approved` source matches the host, and the host hasn't already been granted; revocation is explicit. Hostnames follow the conservative worker allowlist constraints with a strict cap of five. No arbitrary next-host array is accepted. Both the host revision change and attributed append-only audit row commit atomically, with timestamp and session login captured by PostgreSQL.

The future scoped writer is NOLOGIN and can only SELECT its host snapshot and EXECUTE the mutation function, not update state, read editor accounts, or write audit rows. A separate NOLOGIN SECURITY DEFINER executor has the required narrow table permissions. Every migration cycle in CI runs permission, personal role/auth-version, missing-source, reason, grant/revoke, stale CAS, immutable audit, revoked-admin tests and complete down/reapply. No real publishing or runtime wiring has been added.

**Security boundaries still missing:** a real trusted personal-session HTTP handler (the function parameter UUID alone does not prove requester identity), operator review UI, separately provisioned DB LOGIN, source/host authorizer independence policy, durable signed/atomic filesystem export, revision checkpoint, backups and production rollback, and real #17 scheduler acceptance. A recorded reason documents review; it cannot independently prove a publisher's license terms. This migration has **not** run on the VPS.
