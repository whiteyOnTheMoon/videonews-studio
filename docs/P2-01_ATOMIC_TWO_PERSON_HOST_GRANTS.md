# P2-01 — Atomic two-person host approval, offline only

Migration 0023 replaces the dormant PostgreSQL host mutation with a locked, server-side check for a *different* source approver. The latest audit transition for an approved source on the requested host must be an `approve` event by a different editor ID from the proposed host-grant actor. The source registry row is already held `FOR SHARE` and the host approval row `FOR UPDATE`; a concurrent source transition cannot pass between check and commit. The host writer receives audit SELECT, but still cannot write the source registry or audit records. Synthetic PostgreSQL tests require self-grants to fail, independent grants to persist one attributed audit row, and parallel grants to serialize.

**Scope:** This protects cooperating named-editor requests against same-person approval inside PostgreSQL; it does **not** authenticate a SQL caller's asserted editor ID. Production still needs independently authenticated named LOGIN roles, a server-side mapping between DB session and editor identity, personal session/credential lifecycle tests, and a separately accepted truly independent human workflow. No migration is deployed, no VPS/worker change or live feed queries occur. #16 stays open.
