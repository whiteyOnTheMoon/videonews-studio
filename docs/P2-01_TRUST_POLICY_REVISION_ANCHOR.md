# P2-01 — Independent high-water admission for Ed25519 trust-policy revisions

This offline increment links the unmounted rotating-key verifier to a separately supplied policy-revision authority. Each operator-pinned trust policy has a positive monotonic revision and a digest covering the ordered public Ed25519 key fingerprints and epoch boundaries. Verification checks the actual signed envelope and independently approved fetch policy **before** admitting the policy revision. Sources are returned only when both checks pass.

The `IndependentTrustPolicyAnchor.advancePolicy(revision, sha256)` interface is a **required** argument to this dormant entrypoint. Its implementation must be durable, linearizable, reject decreases and same-revision digest conflicts, and be isolated from the worker, publisher and their rollback domains. An in-memory test double is only synthetic evidence; no production anchor or backend connection is provisioned here. A separate hardened authority (possibly an independently administered PostgreSQL service with server-enforced compare-and-advance) and human-controlled bootstrap/recovery must be designed and accepted before wiring the worker. In particular, an untrusted manifest cannot introduce its own signing key, choose the trust anchor or reset high-water state.

This module does not replace the existing source-export high-water anchor. Both the export revision anchor and trust-policy anchor must be enforced before runtime integration. No live source, key, credential, provider request, VPS change or scheduler activation occurs. P2-01 (#16) remains open.
